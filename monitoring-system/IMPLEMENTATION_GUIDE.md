# 实施指南

## 概述

本系统为加拿大金融科技公司提供了一个完整的Redbook和WeChat对话监控解决方案。系统会自动捕获、存储和同步所有客户对话到Google Sheets，同时提供Web管理界面供管理层审查。

## 系统组件

### 1. 消息接收层
- **Redbook Webhook**: 接收小红书平台的消息
- **WeChat Webhook**: 接收企业微信/微信的消息
- **签名验证**: 确保消息来源的合法性

### 2. 数据处理层
- **消息解析**: 解析不同平台的消息格式
- **对话管理**: 自动创建和更新对话记录
- **数据存储**: 持久化存储到数据库

### 3. 同步层
- **Google Sheets集成**: 自动同步消息到在线表格
- **批量处理**: 高效处理大量消息
- **错误重试**: 确保数据完整性

### 4. 管理界面层
- **Web API**: RESTful API供前端调用
- **认证授权**: JWT认证保护管理功能
- **数据查询**: 支持多维度数据查询

## 实施步骤

### 阶段1: 环境准备（1-2天）

1. **服务器准备**
   - 准备一台具有公网IP的服务器（推荐使用云服务器）
   - 安装Go运行环境
   - 配置域名和SSL证书

2. **数据库准备**
   - 选择数据库类型（SQLite用于开发，MySQL/PostgreSQL用于生产）
   - 创建数据库和用户
   - 配置数据库连接

3. **Google Cloud设置**
   - 创建Google Cloud项目
   - 启用Google Sheets API
   - 创建服务账号并下载凭证

### 阶段2: 平台配置（2-3天）

1. **Redbook配置**
   - 在小红书开放平台注册应用
   - 获取App ID和App Secret
   - 配置Webhook URL和Token
   - 测试Webhook连接

2. **WeChat/WeCom配置**
   - 在企业微信管理后台创建应用
   - 获取Corp ID、Corp Secret、Agent ID
   - 配置接收消息服务器
   - 验证消息接收

3. **Google Sheets准备**
   - 创建新的电子表格
   - 分享给服务账号
   - 记录Spreadsheet ID

### 阶段3: 系统部署（1天）

1. **代码部署**
   ```bash
   git clone <repository>
   cd monitoring-system
   go mod download
   go build -o monitoring-system main.go
   ```

2. **配置系统**
   - 复制并编辑配置文件
   - 填入所有必需的配置项
   - 测试配置有效性

3. **启动服务**
   - 使用systemd或supervisor管理服务
   - 配置自动启动
   - 验证服务运行状态

### 阶段4: 测试验证（1-2天）

1. **功能测试**
   - 测试Redbook消息接收
   - 测试WeChat消息接收
   - 验证数据库存储
   - 验证Google Sheets同步

2. **性能测试**
   - 测试高并发消息处理
   - 验证数据库性能
   - 测试同步速度

3. **安全测试**
   - 验证Webhook签名
   - 测试认证机制
   - 检查日志记录

### 阶段5: 上线运行（持续）

1. **监控设置**
   - 配置日志监控
   - 设置告警规则
   - 监控系统健康状态

2. **团队培训**
   - 培训团队使用管理界面
   - 说明数据查看方法
   - 介绍故障排查流程

3. **持续优化**
   - 根据使用情况调整配置

## 常见问题解决

### 问题1: Webhook无法接收消息

**可能原因**:
- Webhook URL不可访问
- 签名验证失败
- 防火墙阻止请求

**解决方法**:
1. 使用curl测试Webhook URL可访问性
2. 检查签名验证逻辑
3. 查看服务器日志
4. 验证防火墙规则

### 问题2: Google Sheets同步失败

**可能原因**:
- 服务账号权限不足
- 凭证文件路径错误
- Spreadsheet ID错误
- API配额超限

**解决方法**:
1. 验证服务账号权限
2. 检查凭证文件路径和格式
3. 确认Spreadsheet ID正确
4. 检查API使用量

### 问题3: 数据库连接失败

**可能原因**:
- 数据库服务未启动
- 连接配置错误
- 用户权限不足
- 网络问题

**解决方法**:
1. 检查数据库服务状态
2. 验证连接配置
3. 检查用户权限
4. 测试网络连接
